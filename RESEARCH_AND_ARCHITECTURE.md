# Paris Restaurant Map - UX Research & Technical Architecture

## Executive Summary

This document outlines the research findings and technical recommendations for building an exceptional mobile-first restaurant discovery map for Parisian food lovers.

---

## Part 1: UX Research Findings

### 1.1 Key UX Patterns from Market Leaders

#### Mobile Map Layout (Bottom Sheet Pattern)
**Reference:** Google Maps, Uber Eats, OpenTable

**Core Pattern:**
- **Map takes 100% of the screen** - Primary visual focus
- **Bottom sheet slides up from bottom** - Contains restaurant list/details
- **Three states:** Collapsed (peek), Half-expanded (list), Full-expanded (details)
- **Gesture-based:** Swipe up/down to expand/collapse
- **Thumb-friendly zone:** All controls in bottom 25% of screen

**Why this works for restaurant discovery:**
- Users can see location context while browsing
- Quick switching between map view and list view
- One-handed operation on mobile
- Reduced cognitive load

#### Filter & Search Strategy

**Desktop:** Sidebar with collapsible sections
**Mobile:** 
- Search bar at top (sticky)
- Filter button opens bottom sheet/modal
- Chips for active filters (dismissible)
- Sort options in dropdown

**Recommended Filters for Paris Context:**
```
Primary Filters:
├── Type (La Table, Street-food, Bec sucré, Boui-boui, Le panier, Cave)
├── Cuisine (Français, Italien, Asiatique, etc.)
├── Budget (€ to €€€€)
└── Arrondissement (1er to 20ème + suburbs)

Secondary Filters:
├── Open Now
├── Metro Line proximity
├── Rating/Note
└── Booking available
```

#### Restaurant Card Design

**Collapsed Card (Peek State):**
- Thumbnail image (left)
- Name + type badge
- Distance + metro station
- Price indicator (€ symbols)

**Expanded Card (Details):**
- Hero image carousel
- Full name + chef name
- Address with copy button
- Metro directions (line + station)
- Description (short + long)
- Opening hours
- "Call" + "Website" + "Directions" buttons
- Share button

#### Marker Clustering Strategy

**Problem:** 227 markers = visual clutter
**Solution:** 
- Cluster when zoomed out (> 15 markers visible)
- Show individual markers when zoomed in
- Cluster color indicates density (green → yellow → red)
- Click cluster to zoom in

### 1.2 Paris-Specific UX Considerations

#### Metro Integration
**Critical for Parisians:**
- Show nearest metro station for each restaurant
- Display metro line numbers with official colors
- Walking distance from station
- Visual: Metro line icons (M1=Yellow, M2=Blue, etc.)

#### Arrondissement Navigation
**Parisians think in arrondissements:**
- Filter by arrondissement (1er-20ème)
- Visual boundary overlay on map
- "Around me" feature using geolocation
- "Near [landmark]" quick filters (Tour Eiffel, Marais, etc.)

#### Mobile-First Gestures

**Essential Gestures:**
- **Pinch** → Zoom in/out
- **Pan** → Move map
- **Tap marker** → Show card
- **Swipe up** → Expand bottom sheet
- **Swipe down** → Collapse bottom sheet
- **Double-tap** → Quick zoom

**Discovery Features:**
- **Shake to random** (like Le Fooding app)
- **Long press** → "What's here?"
- **Pull-to-refresh** → Update data

### 1.3 Performance Optimizations

#### Lazy Loading
- Load visible markers only
- Virtual scroll for list (50 items at a time)
- Image lazy loading with blur placeholder

#### Map Performance
- Use vector tiles (Mapbox/MapLibre) over raster
- Debounce map move events (100ms)
- Cluster markers at low zoom levels
- Preload data in chunks

#### Offline Support
- Cache restaurant data (IndexedDB)
- Cache map tiles for Paris region
- Show "Last updated" timestamp

## Part 2: Technical Architecture

### 2.1 Tech Stack Comparison

| Feature | Leaflet | Mapbox GL | MapLibre | Google Maps |
|---------|---------|-----------|----------|-------------|
| **Bundle Size** | 40KB | 250KB | 150KB | 150KB+ |
| **Performance** | DOM-based | WebGL | WebGL | WebGL |
| **Custom Styling** | Limited | Excellent | Excellent | Moderate |
| **Clustering** | Plugin | Built-in | Built-in | Limited |
| **Mobile Performance** | Good | Excellent | Excellent | Good |
| **Cost** | Free | $$$ | Free | $$$ |
| **React Native** | Yes | Yes | Yes | Yes |

**Recommendation:** MapLibre GL JS
- **Why:** Free, open-source, WebGL performance, custom styling
- **Best of both:** Mapbox quality without cost

### 2.2 Recommended Stack

**Frontend:**
- React 18+ with TypeScript
- MapLibre GL JS (react-map-gl wrapper)
- Tailwind CSS for styling
- Framer Motion for animations
- React Query for data fetching

**Data:**
- Static JSONL (generated by our script)
- No backend needed for MVP

**Hosting:**
- Vercel (frontend)
- GitHub Pages (static data)

### 2.3 Component Architecture

```
App
├── MapContainer
│   ├── Map (MapLibre)
│   ├── MarkerLayer (clustered markers)
│   └── UserLocationMarker
├── BottomSheet
│   ├── Handle (drag indicator)
│   ├── SearchBar (sticky)
│   ├── FilterChips (active filters)
│   ├── RestaurantList (virtualized)
│   └── RestaurantCard (expandable)
├── FilterModal
│   ├── FilterSections (accordion)
│   ├── SortOptions
│   └── Apply/Reset buttons
└── RestaurantDetailSheet
    ├── ImageCarousel
    ├── InfoSection
    ├── HoursSection
    └── ActionButtons
```

### 2.4 State Management

**URL as Source of Truth:**
- `/map` - Default view
- `/map?type=restaurant&budget=1,2` - Filtered view
- `/map?restaurant=123` - Detail view

**Benefits:**
- Shareable links
- Browser back/forward works
- Deep linking support

**Local State:**
- Map center/zoom
- Bottom sheet position
- Selected restaurant
- Filter UI state

### 2.5 Data Flow

```
1. Build Time:
   extract_data.py → restaurants_latest.jsonl

2. App Load:
   Fetch JSONL → Parse → Store in React Query cache

3. User Interaction:
   Filter/Sort → Derive from cached data → Render

4. Map Updates:
   Visible markers → Filter data → Re-render layer
```
